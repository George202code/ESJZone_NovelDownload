# ESJZone 项目结构优化建议

> 检查日期：2026-08-01
> 结论：**核心模块化架构（core/ + scrapers/ + utils/）设计良好，无需重构；**
> 主要问题是**开发残留物堆积**与**配置/双实现不一致**，属于"整理"而非"重做"。

## 二、发现的问题（按优先级）

### P0 — 必须处理

**1. CLI 入口确认（已核实：非双实现）**
- 经代码体检，`main.py` **并非独立旧实现**——它 import 了 `core.cache` /
  `core.downloader` / `core.state` 并调用 `Downloader.download_novel()`，是
  **基于 core/ 的正式 CLI**（含 `--maintain` / `--concurrent` / `--output` /
  `--image-proxy` / `--list-sites` 等完整参数）。
- 与早期"双实现"假设不同，**无需删除 main.py**，只需：
  - 将其本地 `load_config()` 替换为统一的 `core.config.load_config()`（已做，含默认值兜底）
  - 多站点扩展通过 `scrapers/registry.py` 的 `get_scraper(url)` 路由（已做）
- GUI 方案应基于 `core.downloader` + `main.py` 的参数范式，而非另起 CLI。

**2. 配置体系未统一**
- `config.json` 存在但 `Downloader.__init__(config: dict)` 不读它
- `_test_run.py` / 旧 main.py 各自硬编码 dict，密钥/代理易不一致
- 建议：新增 `core/config.py`：
  ```python
  def load_config(path="config.json") -> dict:
      with open(path, encoding="utf-8") as f:
          return json.load(f)
  ```
  `cli.py` / GUI 启动时统一 `config = load_config()`，移除硬编码

### P1 — 建议清理

**3. 开发残留物堆积（23 个文件）**
- `_inspect_cover.py` / `_regen_epub.py` / `_test_run.py` 是有用调试工具，应归入 `tools/`
- `_t*.log` / `_run_*.log` / `_*.err` / `_out.log` / `_test_out.txt` 是运行日志残留
- 建议：
  ```
  mkdir tools
  git mv _inspect_cover.py _regen_epub.py _test_run.py tools/
  rm _t*.log _run_*.log _*.err _out.log _test_out.txt
  ```
- 添加 `.gitignore`：`_*.log`、`*.err`、`_*.txt`、`__pycache__/`、`*.pyc`、`novels/*.epub`、`state/*.json`（状态按需保留可例外）

**4. failed_images.txt / storage_state.json 散落根目录**
- `failed_images.txt` → 归入 `logs/`
- `storage_state.json`（Playwright 登录态）→ **保留在根目录**。`downloader.py` 硬编码
  `os.getcwd()/storage_state.json` 读写，移动会导致每次运行重新登录。只需在
  `.gitignore` 忽略它（含敏感 cookie）即可，不移动。

### P2 — 增强（结合 GUI 规划）

**5. 多站点 registry 已具备基类，缺注册表**
- `BaseScraper` + `DetailScraper` 已实现，但无"按 URL 选 scraper"的路由
- 建议新增 `scrapers/registry.py`：
  ```python
  from scrapers.detail import DetailScraper
  SCRAPERS = [DetailScraper()]
  def get_scraper(url: str) -> BaseScraper:
      for s in SCRAPERS:
          if s.can_handle(url): return s
      raise ValueError(f"无匹配抓取器: {url}")
  ```
- `downloader.py` 改为 `self.scraper = get_scraper(url)`，未来加站只需 append
- 注：GUI 方案文档中"新建 registry"应基于现有 BaseScraper，而非另起炉灶

**6. 目录结构建议最终形态**
```
ESJZone/
├── core/          (cache/downloader/epub/scraper/state/config)
├── scrapers/      (detail.py + registry.py)
├── utils/         (helpers.py)
├── gui/           (PyQt6 实现，后续)
├── tools/         (调试脚本迁移至此)
├── state/  novels/  logs/
├── config.json
├── cli.py         (统一命令行入口，替代 main.py)
├── main.py        (删除或 deprecated)
├── requirements.txt
├── README.md  CHANGELOG.md
└── .gitignore
```

## 四、风险与注意事项

- **勿在整理时改动 core/ 业务逻辑**：缩进/封面/目录修复已验证，只搬文件、不加功能
- **storage_state.json 含登录态**：迁移后务必 `.gitignore`，避免泄露
- **state/*.json 是断点续传依据**：清理日志时不要误删
- **main.py 若被外部脚本调用**：删除前先 grep 引用，提供 cli.py 兼容入口
